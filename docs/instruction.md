目标：在Frida的trampoline中加入采样判断逻辑，使得通过Frida进程插桩的观测程序能够支持采样。
实现细节：
1. Frida有一个上下文结构体ctx，例如在_gum_function_context_begin_invocation函数中会使用成员名来访问结构体成员，为了支持采样，需要在该结构体中最前面加入一个计数器数组，类型为`uint8_t`，因为经典的采样频率为5%-25%，即计数器大小只需到20，就算1%也只需要到100，`uint8_t`最大支持255，够用即可；
2. Frida的trampoline代码是通过调用GumX86Writer等生成器生成的，需要修改trampoline代码生成部分的源代码，在trampoline的代码中加入采样判断逻辑
采样判断的代码逻辑：
1. 在`push   -0xe(%rip)`上下文结构体入栈后，通过fs寄存器获取线程ID；
2. 对线程ID进行简单散列计算(& 63)，得到的散列结果即为计数器数组下标；
3. 对应计数器加1，判断是否达到采样次数（例如20）;
4. 若达到采样次数，则计数器清零，执行trampoline原有的逻辑；若未达到采样次数，则跳转回被插桩的原函数
